pixelmon settings atlas

Every knob in the pixelmon GUI, the pixelmon command line, and the ComfyUI nodes they drive on the rtx render box, with ranges, defaults and a working example for each. Ranges are the limits the controls accept; where a narrower range is what actually looks good, it's called out. Settings marked ⚙ Advanced live in the GUI's rightmost tab.

How a render is built

One prompt and one seed (1000, the ega-sierra-scene preset), changed one layer at a time. Every picture is a real render from the rtx box.

  1. 1

    Prompt → text encoders

    CLIPTextEncode

    Your words, the LoRA trigger, kind/genre/era tags and style guides become the vectors the model steers by. Weighting changes what the picture is about: same seed, one weight added.

  2. 2

    LoRA → the look

    LoraLoader

    The LoRA teaches the model a style. These are the model's raw pictures, before any pixel processing.

  3. 3

    Sampling → from noise to picture

    KSampler

    The sampler removes noise in steps; CFG sets how hard each step pulls toward the prompt.

  4. 4

    VAE decode → the raw picture

    VAEDecode

    The model's full-resolution image. Everything after this point is post-processing on this one picture, so palette, dither and cleanup never change what was drawn.

  5. 5

    Palette node → pixel art, one step at a time

    PixelArtPalette

    Each picture adds one step to the one before it. The zoom below each shows the difference.

  6. 6

    Palette variations

    PixelArtPalette

    Same raw picture, different finishing.

  7. 7

    Transparent background

    PixelArtPalette · transparent_bg

    For sprites: the plain background around one subject is cut away.

Optional inputs

These feed extra pictures into sampling (layer 3).

  1. A

    img2img → start from a picture

    LoadImage → VAEEncode → KSampler.denoise

    The finished study as the starting point, prompt changed to (dragon's treasure cave:1.5), (piles of gold coins:1.4). Denoise sets how much may change. Flat pixel-art start images anchor hard, so real changes need 0.85 or more.

  2. B

    LAB → ControlNet keeps the shape

    Canny → ControlNetApplyAdvanced

    The VGA harbor preset converted to EGA. Shape mode follows the edge map; layout + colors mode keeps its colors too.

  3. C

    Steering → borrow a reference's style

    IPAdapterAdvanced

    Same prompt and seed, one reference image, weight type style transfer. A gentle strength borrows its palette and mood; too much tears the picture apart.

  4. D

    Inpainting → redraw only part

    VAEEncodeForInpaint · crop-and-stitch

    Only the pink area is redrawn; everything outside is pasted back pixel-exact.

No setting matches that filter.
Pipeline order on the server: prompt → CLIP text encode → (IPAdapter steering) → (ControlNet) → KSampler → VAE decode → PixelArtPalette node: smooth/downscale → palette lock + dither → despeckle → 1-px outlines → pixel-art angles → transparent → final nearest resize to the output size. Everything after the KSampler is post-processing, so palette, dither and cleanup never change what the model draws.
